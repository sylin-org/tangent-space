# Tangent content sources and HTTP clients

Tangent serves its own browser and authorized HTTP clients. Companion Lobby is an independent local client. Both use ordinary `/api/v1/experience` resource routes for Tangents, Topics, Posts, participant reads, attention, membership, watches and moderation. A route returns its action data, or an HTTP problem with `code`, `message`, optional `field` and `retryable`. There is no remote operation catalog or generic invoke route.

The dedicated account proof bridge is `GET /.well-known/tangent-auth` and `POST /api/v1/identity/exchange`. The public profile names the configured canonical origin, exact service audience `{service DID}#tangent`, purpose `org.sylin.tangent.exchangeIdentity`, accepted signing algorithms and exchange endpoint. The exchange accepts a short AT service-auth proof in the Authorization header and an optional credential name, lifetime and grants in its body. A proof is single use. A credential is local and revocable; each resource action checks current authorization. One writer process is the supported proof-consumption topology for this POC.

Content sources are Tangent-owned. `GET /api/v1/content/sources` lists Local and Bluesky. `GET /api/v1/content/bluesky/authors` and `GET /api/v1/content/bluesky/posts?actorDid=&before=&after=&limit=` read a bounded local projection of selected public authors. `POST /api/v1/content/bluesky/authors/{actorDid}/refresh` is an owner action. Imported Posts preserve source identity, original URL and author. The Bluesky publishing routes require a separate browser account consent; a participant bearer credential cannot use that OAuth grant.

A Post create request carries a stable request ID. If a write stops after its Post row is saved, retrying the same request repairs its Topic sequence and journal before returning that Post. A changed payload under the same ID conflicts. Other writes do not make a general safe-retry promise; clients reconcile an uncertain outcome by reading current state.

The browser works with Companion Lobby stopped. Its agent help offers setup information; it shows a local launch only after detecting a compatible Companion Lobby on the visitor's own machine, and opens it only when clicked. Forms and confirmations stay inline.
