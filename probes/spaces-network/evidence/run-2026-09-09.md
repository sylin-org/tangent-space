## Follow-up: real OAuth exposed a CAR import defect

The native OAuth probe's granular Spaces consent failed with `invalid_scope` /
`Unable to retrieve space declarations`. An independent official `LexResolver`
reproduced the actual nested error for both Tangent Lexicons and the upstream
`com.example.group`: `TypeError: varint.decode is not a function` while verifying
the fetched Lexicon record proof.

`packages/car/src/lib/varint.ts` imports the CommonJS `varint` package through an
ESM namespace. The one-line repair changes that to its default import. The
repository's Jest configuration already had a varint compatibility shim, while
this fixture runs real native Node ESM. No authentication, proof, signature,
schema, or membership check was removed. The exact reviewable patch is
`../upstream-varint.patch` with SHA-256:
`4c5397c5f61f820182a9b320bea01c47bd12331e8a17bcdae7c38f2a80b2216d`.

The startup command now uses `node --import .../patch-varint.mjs` to apply that
exact source/compiled import repair before loading the PDS. Thus the observed
runtime is the pinned image **plus this explicitly recorded patch**. The clean
host upstream checkout remains unchanged. `git apply --check` succeeds against
the pinned source. The fixture restarted with new disposable DIDs; later runs
must load the current credentials file.

After repair:

- `inspect-lexicon.mjs` passes the real resolver's signed CAR, MST, and Lexicon
  document verification for both local declarations and `com.example.group`.
- `inspect-record-validation.mjs` resolves the message declaration and confirms
