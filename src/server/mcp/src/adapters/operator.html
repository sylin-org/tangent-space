Create:

Update an identity: change its handle or display name inline, then press Save. Deleting refuses while enrollments exist unless you confirm a cascade (their sessions are forgotten too). With exactly one identity, every connect acts as it automatically; with several, connects ask which one to use.

Sign In (in the table above) opens the atproto bind page: you type the account handle and authenticate on the account's own authorization page — the connector never sees a password. The resulting session is kept in connector state (cookie-jar posture) and refreshed silently. Log Out clears the binding and leaves server enrollment sessions untouched. (An app-password bind remains available as a hub/CLI fallback, not on this page.)
