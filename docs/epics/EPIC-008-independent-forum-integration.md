# EPIC-008 — Independent Forum integration slice

Status: local implementation and acceptance complete; public release verification remains, 27 September 2026.  
Canonical cross-product plan: [Companion Lobby EPIC-003](https://github.com/sylin-org/CompanionLobby/blob/main/docs/epics/EPIC-003-independent-forum-integration.md).  
Shared request and endpoint contract: [Forum contract](https://github.com/sylin-org/CompanionLobby/blob/main/docs/design/forum-contract.md).  
Execution state: [Companion Lobby ledger](https://github.com/sylin-org/CompanionLobby/blob/main/docs/epics/EPIC-003-work-ledger.md).

Tangent Space serves its browser and authorized ordinary HTTP clients independently. The local Companion Lobby connector is one client, not a Tangent subsystem. Tangent owns its Space, Tangents, Topics, Posts, local and Bluesky content sources, policies and credentials. Companion Lobby owns a typed Forum capability and maps its generic terms through its Tangent adapter. Tangent offers no remote operations catalog, generic invoke action, model-facing presentation envelope or MCP server schema.

The server worker owns `src/server/web/{Api,Identity,Conversation}` and relevant browser call sites and tests. Preserve useful guided onboarding, persistence selection, authorization and content-source code already in progress. Remove `ExperienceOperations` and the generic `operations` routes, dispatch and associated tests/docs. The existing authenticated resource routes cover all former Forum catalog actions; the canonical manifest records each disposition, including product-only source actions under `/api/v1/content`. Any route-family change lands in browser and connector together without aliases.

The Topic Settings browser pass is part of this slice. One routed Topic page owns details, reading audience, participation, inherited access and Topic-scoped membership/stewardship; the conversation shows a read-only summary and link, not a second editor. Topic managers use actual current `CanManage` policy, with explicit public-history acknowledgement and local form outcomes. The page must work at 375px and by keyboard. Server-wide People and Roles panels do not masquerade as Topic membership. No Topic deletion or archive control is added without a supported domain action.

The only dedicated bridge exposes auth metadata at `/.well-known/tangent-auth` and identity-proof exchange at `POST /api/v1/identity/exchange`. Metadata names the canonical origin, exact audience `{configured-service-DID}#tangent`, purpose NSID `org.sylin.tangent.exchangeIdentity`, proof method and credential policy. Verify current AT Protocol service-auth semantics including required `typ=JWT`, permitted `kid=#atproto` (also the omitted default), issuer `iss` as the account DID, signature, expiry and single-use JTI; no invented `sub` requirement. Independently resolve the participant. Do not accept bare-DID audience or preserve an old MCP-named route/profile as a compatibility path. A short-lived proof yields a narrowed, revocable Tangent credential; subsequent actions use ordinary resource API routes and current authority.

The exchange must claim proof consumption durably before activating a credential. Koan deferred `Save` calls and a process-local `SemaphoreSlim` do not form a cross-instance atomic transaction. The local POC can explicitly support one writer process, with a completed durable claim, fail-closed crash/lost-response semantics and fresh proof on retry. If multiple writers are supported, implement and prove an atomic conditional claim. Test duplicate concurrent and restart replay, interruption after claim, expiry, suspension and revocation. Keep token/proof out of logs.

Post creation uses a resumable single-writer sequence so a retry repairs a persisted Post whose Topic sequence or journal was incomplete. Seeded persisted partial rows exercise that recovery path; an injected storage-failure test remains unverified. Edit and delete have no server-backed same-request retry guarantee, so an uncertain write remains uncertain until read and reconciliation.

Preserve distinct remote publishing consent. A participant credential from the proof exchange cannot borrow the browser's Bluesky OAuth grant, and local Forum posting rights do not authorize publishing to Bluesky. Local and Bluesky source reads remain bounded with source/author provenance. Browser onboarding, normal reading and posting do not depend on Companion Lobby running. The optional Connect an Agent help names an independent client, detects a compatible connector on the browser's machine, and opens it only after an explicit click; the old connector-build/port/call-sequence claims in `wwwroot/connect.html` are removed.

Acceptance requires a clean local server/browser journey, ordinary HTTP client journey, and real connector journey; proof replay/crash and Post partial-failure checks; bounded paging and revocation; relevant .NET/browser suites plus no-dialog and greenfield checks. The Docker development state is disposable: a wipe is authorized without backup after announcing the exact target. No push, public deployment, DNS or Cloudflare Tunnel activation.
