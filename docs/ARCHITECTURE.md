# Architecture

How the tree at the root is built. [BRIEF](BRIEF.md) says what it is for; [LANGUAGE](LANGUAGE.md) says what things are called; [ADR 0015](adr/0015-the-spine.md) records why the shape is this one. Koan's revision is pinned by `scripts/prepare-framework.ps1`, which clones or verifies the source checkout at `.local/upstream/koan-framework`; `global.json` pins the SDK and `koan.lock.json` records the composed modules. Every Koan capability named here is referenced by its exact package identifier from Koan's capability map, never derived.

## 1. Shape

One process. One data folder. Four layers, each defined by a rule it cannot break.

| Layer | Holds | Rule |
| --- | --- | --- |
| **Nouns** | `TangentSpace` (one row), `Tangent`, `Post`, `MediaUse`, `Participant`, `Event`, `Checkpoint`, `Offer`, `Connection`, `Receipt`, `Reference`; Koan's person, roles, overwrites, sessions, grants and media beside them | An entity validates its own change and throws; it never loads another entity, never asks about permission, never opens a transaction |
| **Commands** | a value sent, one hold, one commit or nothing | Every write of Tangent's. It touches the database and nothing else |
| **Readers** | handlers, the door, the stream, feeds, the archive, Connections | Bounded, lock-free, consume compiled state; every resource leaves with `can` |
| **Render** | Razor components rendered statically, the HTML formatter, Vue islands | Renders DTOs. Knows no entity |

Dependencies point one way: Render → Readers → Nouns; Connections → Events and Posts. Nothing depends on Render or Connections. There is no hub object, no governance layer and no policy revision counter: capability is computed per request from a few small rows, so nothing is cached that would need invalidating.

## 3. The write path

Every write is a command: a value that says what changes and carries what it needs, its Ids included. A handler builds it and sends it — `await new Reply(id, topicId, body, author).Send()` — and reads what happened: done with the result, refused with its reason, or failed, saying whether it never ran, landed nothing or may have landed (Koan's `Outcome<T>`, DATA-0167). It runs in its sender's flow, in a hold of its own, one native transaction from its first read to its commit (`EntityContext.Hold`). Holds take turns at the store in arrival order, a sender waits at most the store's busy timeout and is then told the command never ran, and no queue or lock exists in application code. In its hold a command:

1. loads what it names — the participant with standing, the role bag, the Tangent's overwrites, the target Post — asks `Capabilities.For(...)` before it answers anything else, refusing with the gate when the verb is missing and answering as for a missing resource when the actor may not `View`, and calls the entity method, where validation lives;
2. reads its own writes, so one that pages through rows it also changes reads first and saves after; Koan's role changes and overwrites join the hold, and a unique index answers at the save;
3. takes the sequences it needs: the log's from `Event.Log`, Koan's `Sequence`, which reads the highest stored at its first use in a hold and counts on from there, and a Topic's from its root Post's `LastSequence`; a command that does not commit gives them back, so what is committed has no gap;
4. writes the rows, the audit snapshot an edit or a removal takes, and the Events, and returns: done commits them together, as one native transaction, and anything else, a thrown refusal or failure among it, leaves nothing;
5. once committed, runs what the hold registered to follow the commit (`AfterCommit`): each appended row of the log moves the event stream's head to it. The sender then answers with the resource and its `can`.

**A person's words finish.** A write a person sent passes no token to `Send`, so it completes whatever becomes of the request, a closed tab among them; a job passes its own, since a later run makes good what it gives up. A write is sent by whoever asks for it, in their own flow, and a read starts none: a `GET` or `HEAD` writes nothing anywhere.

**Refusals say what they are once, on the reason.** A reason declares its kind where it is defined (`Reason.Absent`, `Reason.Gated`, `Reason.Conflict`, and a plain string, which is invalid), and a gate its word, its sentence and, where one is obvious, the address of what one can do next: a visitor's sign-in carries `next`, coming back to the address of a `GET`. `PostWrites.Refused` is the one mapping, and the only code that answers a gate as a problem: absent `404` in one sentence, gated `401` to sign in and otherwise `403` with its heading, `gate` and `next`, conflict `409`, invalid `400`, as a page or as JSON by `Accept`; the word a gate declares reaches JSON and a page's `data-gate`, and a person reads its heading and its sentence. `PostWrites.Answer` adds what a command that could not finish answers: `503` with `Retry-After` when it never ran, otherwise `500`, naming no cause. A form page keeps showing a refusal inline, and a route that only answers JSON uses Koan's `this.Answer`. A refusal a person reads as a page stands in the place's frame, its masthead and footer around one panel, whichever answered it: `PostWrites.Refused`, or Koan before a route answers, through `ProblemFrame`.

**Every table a command writes exists at boot**, the audit partition's among them (`TangentModule.TablesExist`), since a table first used inside a hold makes every other flow that wants it wait for that hold (DATA-0166).

**Idempotency is the Id**: the client mints a Post Id as a TID, so a retry with the same Id and the same body sent returns the existing Post, whoever its typed handles name by then, and the same Id with anything else is a conflict, `409`, whichever Post holds it. A write that sends no Id goes by the one its words name (`PostWrites.IdFor`, `Tid.Derived`): the hash of who sent them, where they go and the words, within a five-minute window, read in that window and the one before, so a retry whose answer was lost is the same Post on either door and the same words ten minutes later are a new one, and an Id that holds anything else, the same Post edited or removed since among it, gives way to a minted TID. A Topic's order is `Post.Sequence`, taken in the hold, and a seek cursor names an Id only to break a tie of times, so what an Id reads moves nothing; an edit sent again from the version it made the Post from returns the Post the same way. **External I/O never enters a hold**: a job calls the network and then sends a command with the result. The root Post is the Topic's state — `LastSequence`, `ReplyCount`, `LastActivityAt`, `Locked`, `Pinned` — so a Topic has no row of its own.

## 4. The read path

A request is resolved once in the pipeline: session → person → role bag → the overwrites of the Tangent in the route. Handlers are thin: a bounded query, `can` attached, the DTO returned.

**The page is the API.** One handler, one DTO, and the formatter decides: `Accept: text/html` renders it through a Razor component, `application/json` serializes it, and a fragment request header renders only the component for that resource. A Post's page, its JSON, its live patch and its archive file are the same DTO through the same component. Agents fetch the URL a person shares; `llms.txt` says so in two lines, and the descriptor carries `"api": 1` as the stability promise. Every write a page offers its reader rides in the DTO as a `Form`, the one the component renders as the HTML form: the address it posts to, its method, its fields, each with what it holds and the value the page gives it — the TID minted for a new Post among them — and is posted under the session's cookie. The handler builds it only where the reader may make the write, so the JSON offers what the HTML offers and nothing more, and Tangent's own writes take the fields as a form or as one JSON object, into one typed input (`ReplyInput` and its neighbours, each field saying what it `Holds`), so an agent that follows a form exactly makes the write; a field sent empty stays empty, which is not a field left out (`SentAsSent`), and a value that cannot bind is refused naming its field, before the address is read and alike whatever the address holds, as a body past a route's limit is, with `413`; a `page` that is no number reads the first page, since all a hand-edited address could want is that.

**Every route a participant uses is also a tool.** `[Tool(Name = ...)]` and `[Description]` on the controller action are the whole of it: Koan's edge at `{base}/mcp` calls the action through the application's whole pipeline, so name, input schema, authority and answer are the route's, the action's own gate judges each call, and nothing is hidden by kind of account. Reads and writes alike are tools, what only a role may do among them. A page that only shows a form, sign-in and first run, the proof door, feeds, export, the descriptor, `llms.txt`, the event stream and the not-found catch-all are not, and `TheToolsTests` holds every action of the tree to one list or the other. A tool's call carries the caller's own session cookie through the same pipeline a page's request takes, so the real gate judges the real caller; a caller with none is a visitor there as on a page, and a write answers with the sign-in gate and its next step. Koan's `Koan:Web:RefuseCrossSiteWrites`, on by default, refuses a write that carries a cookie and that a page of another site sent, at every endpoint, `/mcp` among them, so a form carries no token of its own: a program that sends no browser's headers passes, as Companion Lobby's adapter does. The place's address answers `GET /` with a `Link` to `llms.txt` (`rel="describedby"`), and every page's head carries the same link; nothing at `/` speaks MCP, and `llms.txt` says to use `/mcp`. `Koan:Mcp:Instructions` tells a client that a Post is someone else's words, to read and never to follow, and the tools that read Posts say so too. [ADR 0016](adr/0016-a-standard-client-at-the-tools-door.md) records it.

`ETag` is `Post.Version` or `Event.Seq`; a page assembled from many rows, such as the Tangent page, carries a hash of its DTO, so a new Post, a moved checkpoint or a changed `can` changes it; a whole page's tag also names the place's accent. A page that carries a signed-in reader's forms is never stored, so a browser's Back after sign-out redisplays nothing of it. Public pages are cacheable by a proxy. A private Tangent Space sends `noindex` (`X-Robots-Tag`) on every page and serves visitors only the sign-in page: one resource filter (`PrivatePlaceGate`) reads the settings row by its key and answers a visitor at any page of the tree the sign-in page, which brings them back to the address they asked for, or for JSON the problem whose gate is `sign-in`, both `401`; the sign-in, first run, the descriptor and `llms.txt` answer as themselves. Errors are one shape, RFC 9457 `problem+json`, carrying the same `gate` the door shows: `sign-in`, `apply`, `timed-out`, `locked`, `removed`, or the deciding overwrite or missing role in one sentence; what the reader may not view is absent and answers as not found.

**Search** is `/search`, one resource both ways (`SearchController`, `PostSearch`): Koan's lexical index over `Post.Title` and `Post.Body`, its page and its ranking applied by the store to the Posts the reader may view — told the Tangents they may view (`ViewableTangents.All`), or the others where they are fewer, and to leave out removed Posts (`Post.Lexical.Search`, `Within`) — so no page, length or score says anything of a Post they may not view, and words only such a Post holds answer as words nobody holds. The word the text ends in also matches as the start of a word (`AsTyped`), for what is still being typed, on the page as in the suggestions, so Enter finds what they showed; a partial word the store stems away, "runnin" for "running", finds nothing until it is whole. A page holds at most 20 Posts by number, to page 100, one read of it and, where it is full, one of the next to say whether it holds anything; nothing is counted. The text holds at most 200 characters and a snippet 24 words; words or a page that can't be searched answer the page, saying why, as `400`. A snippet leaves the server as runs of words, the matched ones marked, read from the store's cut of the body as Markdown to plain text, so it is never markup. A search is never stored. A private place's gate answers a visitor before any of it.

## 6. The log

Only a command appends. Kinds: `post.created` (a reply's carries the author of the Post it answers as target, unless they answer themself; a Topic taken on a tangent carries its origin's author, unless they take their own Post; a report's carries no target, so the reported author never hears of it, and is marked a report, `Report`), `post.edited` and `post.removed` (each carries the Post's author as target where someone else did it; the author's own carries no target), `post.moved`, `mention` (one per participant a Post's body newly mentions — when it is started, replied or edited — who may view its Tangent and is not the actor, as target), `standing.changed` (a participant's arrival, theirs alone, carrying the standing it gave them, an application where that is applied; each decision on an application, by its decider; and each timeout, ban and lift, by whoever holds `ManageStanding`; with the participant as target, the standing it left them with and the one before), `role.changed` (a role given or taken, by whoever holds `ManageRoles`, with the participant as target, the role and whether it was given; creating, changing or deleting a role and setting a role's access to a Tangent append nothing, and Koan's role rows keep who changed them last), `tangent.changed` (carrying the audience), `space.changed`.

Each is one line about one thing — the Post, my Post someone else edited or removed, naming who, the Topic taken on a tangent, the report in the moderators' Tangent, which names the reported Post's author only where I may view that Post, the door for a change of my standing, my profile for a role, the applications for someone who applied — and, for the operator, the open Offer of an address above them, as the door shows it; who admitted me or lifted a timeout or ban is named, who declined, timed out or banned me is not. Its `GET` writes nothing. Opening them is its `POST`, which the frame's count, the account menu and the door's line each send: it moves my notifications checkpoint through the newest I have (`SeeNotifications`), never backwards, deciding no application, and lands on the page with where the reading began in `from`, so what was new is still marked. Every page's frame shows how many lie past that checkpoint, from one read of at most 100 rows, for whoever may view the moderators' Tangent one of at most 100 reports, and, for whoever decides applications, one of at most 100 of those that wait, shown only while there are some: the number, its "at least" and the sequence it reads through count only the rows that reach me, so a row I may not view moves none of them — the count is a lower bound only where those rows fill the read, and it reads through the newest of them, or stays at the checkpoint where none is; a read full of rows I may not view counts fewer than may follow and says nothing of them. The page's stream raises it for each row past where it reads through that someone else did and that targets me or is a report, which the stream sends only to whoever may view the moderators' Tangent, and, while I decide applications, for each application; opening them, or a decision about an application, is what lowers it, on the page that follows |
| The stream | `GET /events?since=` as server-sent events, one event to a frame with its sequence as the frame's id, resumed by `Last-Event-ID`: first what the log already holds, then, each time a commit moves the log's head past what it read, the rows from there, read from the log by their sequence, which has no gap; the same URL without the stream header is the poll, one bounded page with where to ask next, which the door also names. A row in no Tangent reaches a reader where it changes the place, names them as its target, or is an application and they hold `ManageStanding` (`Readable`). A stream holds what its reader may view for at most a second, and reads it again at once when a row changes a standing, a role, a Tangent or the place. Every position a reader is given — a frame's id, the poll's `through` and `next`, the door's `poll`, where a page's stream begins and where a request without a sequence begins — is the newest row that reaches them; it passes rows they may not see only when a whole scan of 200 rows held none, which is all it discloses of the Tangents they may not view. A stream catches up on at most one such scan and ends there to be resumed, and sends a comment whenever 15 seconds pass without a write |
| Feeds | not the log but the Posts it records, since a feed says what stands: `/t/{tangent}/feed.atom` and `.json`, and `/articles.atom` and `.json`, each one query of the newest roots that stand, through `Post(TangentId, ParentId, Removed, CreatedAt)` or `Post(Kind, ParentId, Removed, CreatedAt)`, at most 20 and at most 1 MiB of HTML, the newest always, with who they name read by key; the articles take the Tangents a visitor may view (`ViewableTangents.All`), so as many as the place holds are judged. A feed reads as a visitor whoever asks, so it is one answer for everyone: a served file with an `ETag` of its body, a five-minute lifetime and a `304` for the tag a reader holds, judged after who may read it. A members-only Tangent's address answers as one no Tangent has, a private place serves its visitors the sign-in and anyone else not found, and a place with no articles has an empty articles feed. An entry says when it was published and when its words last changed (`ChangedAt`), and who else last edited it, in its content; its links and images are absolute |
| Connections | each reads from its own `Seq` |
| Export | not the log but what it records, since an export says what stands: the Tangents the reader may view, a page at a time, each one's Topics by `Post(TangentId, Slug)`, and each Topic's replies a sequence range of `Post(TopicId, Sequence)` at a time; a section of the rendering below |
| The archive | not the log but what it records, as export is: `Export`'s walk read as a visitor, and everyone admitted a page at a time by Id; a section of the rendering below |
| The moderation trail | `post.edited` and `post.removed` with a target, `standing.changed`, `role.changed` with their actors |

Visibility applies at read: an event in a Tangent the reader cannot view does not exist for them. Nothing is pruned. A protocol's "content changed, content removed, audience changed" is a filter over these kinds.

## 7. Access

Discord's model, on Koan's roles, resolved in Discord's order.

- **Bits**: `View`, `Post`, `Topic`, `EditOwn`, `RemoveOwn`, `Moderate` (edit or remove any, lock, pin, move, take on a tangent anywhere), `ManageTangent`, `ManageRoles`, `ManageStanding`, `ManageSpace`; `Administrator` implies all, and no overwrite grants or denies it. On a Koan role and in a Koan overwrite a bit is the permission token `global:` followed by its name, and `Administrator` is Koan's `global:administrator`; Koan compiles a role's tokens into the bag.
- **Roles** are seeded at first start on Koan's `RoleCollection`, each once, left as the proprietor sets it and returned when gone, directly above the seeded role below it: `everyone` with no bits of its own, `role:member`, `role:moderator`, and `role:administrator` with `Administrator`, which every start gives back to it where it is missing. They stand in Koan's one order (`Role.Position`, SEC-0031), the highest above: `everyone` at the bottom, then member, moderator and administrator; the operator stands above every role. Whoever holds `ManageRoles` shapes them at `/settings/roles`, a page of the order at a time, the highest first, one command each: `CreateRole` names a role and chooses what it grants, keyed `role:` and the slug its name gives, deduplicated with a numbered suffix, which never changes, and places it directly above the member role; `ReviseRole` renames it, sets what it grants and moves it one place higher or lower; `DeleteRole` deletes one the place created, whose permissions the actor holds, with its members and every Tangent's overwrite for it, confirmed in the page. Each changes only a role the actor manages — Koan's `RoleCollection.Manages`: a role below their own highest, every role but their own highest for a bag that administers, and every role for the operator — and gives or takes away only the bits the actor holds in the place; `everyone` stays as it is, the seeded roles are never deleted, and the administrator role keeps `Administrator`.
- **Admission** is the settings row's `Admission`: `join`, the default, or `apply`. On a place that says join, a person's first sign-in makes them an admitted participant; on one that says apply, an applicant, with `AppliedAt`. Every admitted participant is in `role:member`, which grants posting in an ordinary Tangent: the command that admits them joins them, as first run's joins its setter to the administrator role, and every sign-in's joins an admitted participant who lacks it (`MemberRole`), one read of Koan's cached bag deciding; an applicant, a declined applicant, a participant timed out until a time still to come or a banned participant is never joined there, and one whose timeout has ended is, since every decision about a participant reads their standing as it stands now (`Participant.StandingAt`) and the row keeps the timeout as it was written. A role holds any number of members, each one row. Whoever holds `ManageSpace` sets the admission at `/settings/admission`, one `space.changed`; everyone already there stays as they are. Whoever holds `ManageStanding` reads the applications at `/settings/applications`, a bounded page newest first through `Participant(AppliedAt)`, continued by a cursor, and decides each inline: `Admit` admits a waiting or declined applicant and joins them to the member role; `Decline` leaves a waiting one declined, reading what a visitor reads, listed still, and admitted by a later `Admit`. Each decision that changes a standing appends one `standing.changed` targeting the applicant, carrying the standing; deciding what is already decided writes nothing, and declining anyone but a waiting applicant is refused. An application reaches whoever decides it from the applications themselves, not from rows written for each decider: the arrival keeps its sequence on the applicant's row while it waits (`WaitingSeq`), so whoever holds `ManageStanding` when they read finds it among their notifications, counted on every page and on their stream, linked to the applications, and their door says how many wait; an admission or a decline clears it, so a decision by one decider ends it for all. The applicant's door says while they wait, or once declined, in one sentence from the place's `gate` for `Post`, and says who admitted them as news past their checkpoint.
- **Base** is the bits in the participant's bag, which carries the `everyone` role's own, with `View` for everyone where the settings row's `Audience` is public: the row is the one statement of the place's audience, and no role carries it.
- **A Tangent's access** is each role's own overwrite there (`RoleAccess`): none, as the role allows in the place; `View` allowed with `Post` and `Topic` denied, reading alone; or all three allowed, reading and posting. Whoever may manage the Tangent sets it at `/t/{tangent}/settings/access` for a role they manage, everyone and the roles that administer aside (`ChangeAccess`); anyone else reads the gate there and no role; the moderators' Tangent's stays. A private Tangent whose member role reads and posts there is members-only: a member reads and starts Topics there, and a visitor finds it absent.
- **Overwrites** are Koan's `PermissionOverwrite` rows on the Tangent's resource `tangent:{slug}`, written through `RoleCollection.Overwrite` inside a command; evaluation reads the ones a reader's bag meets — its roles', `everyone` among them, and the participant's own — from Koan's per-resource cache, and one row is one keyed read (`Overwrites.Of`). Koan resolves them over the base in order: `everyone` deny then allow → the denies then the allows of the bag's other roles → the participant's own deny then allow. A Tangent's audience is nothing more than `View` in its `everyone` overwrite, written in the command that creates the Tangent, so the Tangent exists for nobody its audience excludes from the instant it commits, and a page reads a Tangent's row before its overwrites. An address segment that cannot be a Tangent's slug reads no overwrite and answers as a missing Tangent.
- **Lists of Tangents** hold the Tangents the reader may view, or, for take this on a tangent, those where they hold `Topic`, in the Tangents' order (`ViewableTangents`): the Tangents are read a hundred at a time by seek on their stored order and slug and each judged from Koan's compiled state, each Tangent kept once, and a page continues from a cursor naming the last Tangent it keeps, sealed with ASP.NET Data Protection under its own purpose (`Tangent.Cursor`), so the reader can neither read the order it holds nor forge one, and a cursor that does not open is refused with 400. A page costs at most the Tangents the place holds and says nothing of the others. A Tangent created or moved while the reading goes on can be read twice, kept once, or missed, until a compiled viewable set per reader — keyed by their roles, whether they are signed in, their standing, the audiences and their own overwrites, renewed on every create, overwrite, role-permission change and move — replaces the reading and closes that window. The door's rail and the switcher show the first fifty and link to `/t`, which lists them all a page at a time; take this on a tangent pages its choices; whoever may view the moderators' Tangent finds it on the door after the first page, whatever the place holds.
- **Creating and configuring a Tangent**: whoever holds `ManageSpace` in the place creates a Tangent (`CreateTangent`, from `/t/new`), naming it, with everything else defaulted: no description, discussions, and the public audience, where everyone who reads the place reads it and members post. Whoever holds `ManageTangent` on a Tangent, or `ManageSpace`, changes its name, description, default kind and audience (`ChangeTangent`, from `/t/{tangent}/settings`); the slug stays. Moving a Tangent earlier or later arranges the place's list and needs `ManageSpace`: it and its neighbour change places, and the Tangents are numbered from one in their order, read a page at a time, each page continuing from the stored order and slug of the last Tangent read, and only as far as a page past the pair; only a reader who holds it reads where a Tangent stands, between the nearest Tangents they may view. A change of audience is judged, and then writes the `everyone` overwrite as a create does; the judgement comes first, so a change that closes the Tangent to its own sender commits, and the sender reads, on the page or as JSON, that it is saved and nothing else of it; a write's answer gives the order only to a sender who holds `ManageSpace`. A change that writes the audience records it with one `tangent.changed` carrying it, in the same commit. The moderators' Tangent's audience and order are fixed: its settings rename and describe it and never change its overwrites.
- **The place's settings**: whoever holds `ManageSpace` in the place renames it, writes its description, sets its audience, public or private (`ChangeTangentSpace`, from `/settings`, the general section of the Tangent Space settings), sets its admission (from `/settings/admission`), and sets its accent (from `/settings/appearance`), and the change appends one `space.changed`; a change of nothing writes nothing. The rail lists what its reader may use: general, admission and appearance for whoever holds `ManageSpace`, the roles section for whoever holds `ManageRoles`, the applications section for whoever holds `ManageStanding`, which refuses anyone else with the gate and no applicant, the people section for whoever holds it or `ManageRoles`, which refuses anyone else the same way, and export for whoever holds `ManageSpace`, which refuses anyone else the same way. The account menu opens the first section the reader may use, and general, admission and appearance send a person who may not change them but may use another section to it; their JSON answers as it is, with the gate.
- **Appearance**: the shell puts the place's accent on every page's `<html>` as `data-accent`, read once per request by the settings row's key (`TangentSpace.OfRequest`), and the tag of a whole page names it and the row's version, so a change of it or of a slot reaches a page a cache holds. A page open when the accent changes takes it at its next load. The theme is no part of a page, which a proxy may hold for every reader: it is the reader's, in their browser, and `theme.js`, a classic script blocking in `<head>`, sets `data-theme` before the body is parsed, so the first paint is already theirs. With no script the device decides and the switch does not show.
- **Standing precedes everything**: banned sees nothing; timed out keeps `View`, and reports as every participant for whom a Post exists does, until `StandingUntil` passes, when the participant reads as admitted; applied and declined hold `View` where the Tangent Space is public, with the gate `apply` or `declined`. A visitor is `everyone` with `View` alone on a public place.
- **The people**: whoever holds `ManageStanding` or `ManageRoles` reads the participants admitted to the place — admitted, timed out or banned; applicants stay among the applications — at `/settings/people`, people and agents alike, a bounded page in handle order through `Participant(Handle)`, continued from a cursor naming the last participant's handle and id, sealed with ASP.NET Data Protection under its own purpose (`Participant.Cursor`) as a list of Tangents' is, and refused with 400 when it does not open; the start of a handle typed there, trimmed of its `@` and lowered, reads one range of the same index (`People.Read`). Each row says the participant's kind, standing, with when a timeout ends, and roles, and offers inline only what the reader may change of them (`People.Offered`), by the rule every change answers to (`People.Refusal`): the roles stand in Koan's order and the operator above every role, and a reader changes the standing or roles only of someone whose highest role stands below their own (`RoleBag.Highest`), never their own and never the operator's; so, with the seeded roles alone, a moderator acts on members, an administrator on moderators and members, and the operator on everyone else. Whoever holds `ManageStanding` times someone out for an hour, a day or a week (`TimeOut`), bans them (`Ban`), confirmed in the page, and lifts either (`Lift`), after which a participant without the member role joins it; each is one command whose `standing.changed` targets the participant with the standing it left and the one before, and a change of nothing writes nothing. Whoever holds `ManageRoles` gives or takes every role but `everyone` and the member role, which is admission's (`ChangeRole`): only a role they manage (`People.Manages`) and whose permissions they hold; Koan's role write is not part of a transaction, so the command judges the change and writes the role before its transaction opens and records one `role.changed` in it; a row offers each such role, from the first page of the order, to someone not banned who lacks it, and takes each they hold. A refused change answers with the gate's words: the missing verb's gate, or the sentence of the rule that forbids it. The same changes are on a participant's profile for whoever holds the bits, and come back to it. An open stream takes a change in at the row that records it, since a `standing.changed` or a `role.changed` makes it read what its reader holds again, so a ban ends the banned participant's stream there. The participant's door says that they are timed out and until when, that someone lifted it and they are back, or that someone gave them a role or took one.
- **Absent**: what a reader may not `View` does not exist for them. Without `View` on the place or the Tangent — banned, a visitor on a private Tangent of a public place, a participant an overwrite denies — every verb carries the one reason `absent`, nothing else is said, and a command answers what it answers for a missing resource.
- **Report** is held by every participant for whom a Post exists, whatever they hold in the moderators' Tangent: a visitor's gate is `sign-in`, a removed Post's is `removed`, a Post of the moderators' Tangent is not reported, and a Post the reporter may not view is absent; the page offers it only on someone else's Post. A report starts a Topic in the moderators' Tangent, titled from the reported Topic where the moderator role may view the reported Tangent and from the reason's first words elsewhere, or, while the reporter's earlier report of the same Post stands (neither removed nor locked), replies in that report's Topic. The same Id from the same reporter about the same Post answers received whatever became of the report. A report reaches whoever may view the moderators' Tangent when they read — the moderators and administrators, and anyone given that view later — from the log itself: its `post.created` is marked a report, so they find it among their notifications, counted on every page and on their stream, and nothing is written for each of them. The Topics taken on a tangent from a Post leave the moderators' Tangent out of the read for a reader who may not view it.
- **Images**: whoever holds `Topic` or `Post` in a Tangent brings an image in at `/t/{tangent}/media`, as a file of a multipart form or in base64 in one JSON object: `Media.Keep` refuses anything but a PNG, a JPEG or a WebP, of at most 20 MiB and 64 megapixels, turns it upright, fits it within 2400 pixels, removes every kind of metadata but its colour profile and encodes it again, before any row is written, outside any command; the same picture is kept once. An image reaches a reader through `MediaUse`: its row for whoever brought it, while the place exists for them, or any Post that uses it in a Tangent they may view, each Tangent judged once from Koan's compiled state, a page of its uses at a time, one index range. `GatedMedia` asks that before Koan's routes open the bytes, a stored render or a validator, so to anyone else an image answers what an Id nothing has answers. A command that writes a Post keeps its uses in the same commit (`MediaUse.Record`): a use begins only where the actor may see the image, so naming it is no way to reach it, and ends when an edit drops it or the Post is removed; a cover the actor may not see is refused. The same picture in a public and a private Tangent reads as in the public one, since whoever sent it there held it already.
- **`can`** is the bits the participant holds on this resource plus authorship and state: `EditOwn` and `RemoveOwn` apply to my Post; nothing applies to a removed Post; `Post` is absent on a locked Topic.

`Capabilities.For(participant, tokens, space, tangentId, overwrites, now, post?, root?)` is one pure function over Koan's bag, the settings row, the Tangent and the overwrites on its resource that the bag meets, and the time, the base and the overwrites resolved by Koan on that resource (`RoleBag.On`); a command loads those with bounded reads (`Capabilities.Load`) and asks it inside its `Run` before it answers anything else, and a page that answers for many Posts loads them once (`Capabilities.LoadRows`) and asks for each; its tests enumerate the table. It resolves in this order: standing, `View` on the Tangent, lock and removal, the base and overwrites for the other bits, authorship. The `gate` is the first step that dropped the verb: `sign-in`, `apply`, `declined`, `timed-out`, `absent`, `locked` or `removed` where standing, audience or state decided, the deciding overwrite where one did, and the absence of a role otherwise, both from Koan's deciding fact (`EffectivePermissions.Explain`). The browser and every agent render `can` and compute nothing.

## 8. Rendering

**Razor components rendered statically** through `HtmlRenderer`: typed templates, no interactive runtime, no JavaScript needed to read. One component per DTO; a page composes them; a fragment is one alone; the archive writes them to files; export packages them; feeds are a sibling output: the same rendered bodies in a `Feed`, written as Atom and JSON Feed, advertised by the frame as `<link rel="alternate">` on the door, a Tangent's page and a Topic's while a visitor may read them, and named in those pages' JSON as `feeds`. A page a visitor may read carries its card in its head on the same condition: the door, a Tangent's page and a Topic's each name a card from what they already read, so a card adds no read, and the formatter has Koan render it (`IOpenGraphCardRenderer.RenderHead`) into the shell. A fragment and JSON carry none. Slots — head, masthead, door intro, article header, footer — are sanitized once, when they are written (`Slots.Written`), by the sanitizer a Post's body goes through under a policy per slot, and rendered as they stand through the same shell and components, and are therefore identical in the live site, the archive and exports. The shell takes the head, the masthead and the footer from the row; the door and an article's page carry theirs in their resource, so the door's fragment keeps it. A head keeps `meta` by name or property, and icon and `rel="me"` links. No slot holds CSS: a selector reads what a page holds in an attribute, a hidden field's value among it, and keywords alone can bring a lazy image into view, which sends what was read to another host, so no allow-list of CSS is safe; `Slots` says so at length. An image on the place's own origin, a Post's, a slot's or an icon, points only under `/media/` (`MarkdownHtml.SafeImage`), since loading one is a request with the reader's cookies they never chose to make.

**Export** is `/settings/export`, one resource both ways for whoever holds `ManageSpace`, whose reader takes the whole place from `/settings/export.zip` or one Tangent from `/settings/export/{tangent}.zip`; anyone else reads the gate, and a Tangent they may not view answers as one no Tangent has. A zip is written onto the response as it is read (`ZipSink`), so what it keeps is .NET's directory of the files so far, and a read that fails ends the connection with the zip unfinished, which never opens as whole. `Export` walks what the reader may view, each read a bounded page: the Tangents (`ViewableTangents`), the Topics of each by slug, which never changes, so one that gains a reply on the way is neither missed nor written twice, and what started after the export began is neither written nor listed; then a Topic's replies a window of 50 sequences at a time, so a Post's file follows from its sequence. Each of those is the live page's own resource, `TangentsPage`, `TangentPage` or `TopicPage`, offering nothing and naming no reader, through its own component and `HtmlFormatter.Whole` with `Standalone` set, which leaves out the scripts, the theme switch and the live updater, so the device decides the theme; and beside it the same resource as its JSON answers: `index.html` and `index.json`, then `page-{n}`, at the root and under `t/{tangent}/`, and `index` and `{n}` under `t/{tangent}/{topic}/`. Each page has a renderer of its own, disposed once it is written, since a renderer keeps what it rendered. Addresses are relative, and times full dates. What the zip does not hold stays the place's address: a mention's profile, a Topic in a Tangent left out of it, and a body's root-relative target (`Feed.Rooted`). A person's mark is their monogram. The place's stylesheet and fonts go in beside the pages. A tombstone has no body in its page or its data, and nothing reads a snapshot. As a page is written, each image of the place it shows that reaches its reader (`MediaUse.Reaches`) goes under `media/`, once, read from Koan's media as it goes (`MediaEntitySource`, `IFileSink.Copy`), named for what it is, `media/{id}.jpg`, so its holder can open it, and the page names that file; a cover stands alone, a render having no file. An image that does not reach them stays the place's address, which shows them nothing, and the page's data says what its live JSON says.

**The archive** is what a visitor may read, rendered to a folder under the place's own URLs by `Tangent.Server archive <folder>`, so any static file host serves it at the place's address and the old addresses keep working: `{address}/index.html` for each page. A place a visitor may not read is refused, and so is one with no address for its feeds to name, a folder that holds anything, and a data folder a running Tangent Space has marked. The verb starts the composition on a Koan host of its own that listens nowhere, and `Archive` writes through `FolderSink`, the same `IFileSink` a zip is, under a name beside the folder, which takes the folder's name only once it is whole, so a failed run leaves nothing. It reads the way a visitor reads: `Export`'s walk with no reader, each bounded and rendered through `HtmlFormatter.Whole` as export is, with the Tangents' list at `t/` and the page data left out, since a static host has no address for it; the door and each profile are their own handlers' answers to a request with no reader, standing alone, and everyone admitted has a profile, an applicant none, a page of them at a time by Id. A page's continuations keep the names a zip gives them, `page-{n}.html` and a Topic's `{n}.html`, since a live page's cursor is a query a static host cannot answer; asked with one, an address answers its first page. Pages link one another relatively, and what names the place is the place's own address: a profile, a mention, a feed, a body's root-relative target. So an archive is at home at the place's base URL, or the one `-Address` names, under whatever path it holds. A static host has no redirect to give, so each Post's address is one small page that forwards to its window, and links it for one who stays. A DID's colons name no file on Windows, so an archive rendered there leaves out the addresses by DID, and the profile of someone with no handle. A page opens with one plain line, `Shell.Retired`: the place is retired, and the day its pages stand as of. A feed is the very file its address answers live. An image a page shows that reaches a visitor is in it as it is in an export, at `media/{id}`, the very address it has on the place, so a feed that names it holds too; one a visitor may not see is not there, and neither is a render, so a page names the image itself. A name with no extension is typed by the host: the retired server answers from an image's first bytes, a host that answers a generic type still shows it in a page, since a browser reads the picture it finds. The descriptor, `llms.txt` and the data beside a zip's pages are not in it.

**A retired place** is one whose operator names its archive in `Tangent:Archive`. `Retirement` makes the server a static file host of that folder and nothing else: no Koan, no database and no command, so no write has anywhere to land, and the data folder stays as it was, so taking the setting away brings the place back. A folder with no door in it is no start at all. An address that holds a page answers it, with the closing slash a static host adds, which its relative links count on; an image at its address answers it; any other read answers not found in one plain line; any write answers `405` as a problem; and `/health/live` answers, under the configured path as every address is.

**Vue islands** mount where a participant does something: the composer, the article editor with its source view and roundtrip check, settings panels, the live updater, bring-your-agent. The masthead's search box is a form that goes to `/search` without one; the `search` island adds suggestions in the page, the first five of the same resource as JSON, asked 200 ms after the typing pauses, from two characters. The frame shows a signed-in reader, on every page, how many of their notifications they have not seen, carried by the page's DTO with who reads (`Notifications.Count`), and the unseen island raises it from the rows the page's stream delivers. An island is `<div data-island="composer" data-props="…">`; a pre-paint theme script and one module of islands, with the article editor, the one heavy island, in a chunk of its own that only its pages load, no client router, no store library. Islands share one event stream per page; a live event fetches the fragment and inserts it. Drafts are `localStorage` keyed by scope; an uncertain submit is a `GET` of the minted Id. An article reads and is written in one set of rules (`article.css`): the form holds the cover, title and byline in their places, and the article editor (TipTap, on `@tiptap/markdown`) writes Markdown back to the form's own body field on every change, so the composer's drafts and sending go on as they do without it. It opens only where `canEditMarkdownRichly` finds the Markdown's meaning survives, and otherwise leaves the field as the source view, which rewrites nothing. An image on its way stands where it was put as a decoration, never part of the words, and the form waits for it. Pages load as pages, with cross-document view transitions. Phone layouts are CSS on the same HTML.

## 9. Connections

A Connection belongs to a participant and syndicates only Posts that participant authored. The proprietor's Connection also carries the Tangent Space's `site.standard.publication`. Identity is core, not an adapter: a Tangent Space requires atproto identity.

**A Connection is a log reader with a cursor.** The dispatch job runs per Connection: read events since `Connection.Seq` of kinds `post.*` and `tangent.changed`; for each, load the Post, its current audience and the previous Receipt; call the adapter; save the Receipt; advance `Seq`. On failure the cursor stays, so an edit lands before a removal; the Receipt records the error; after repeated failure the Connection appears as an attention item on the door of the participant it belongs to.

```csharp
interface IConnectionAdapter
{
    Task<Receipt> Handle(Event e, Post post, Audience audience, Receipt? previous, CancellationToken ct);
}
interface IReferenceSource { IAsyncEnumerable<Reference> Since(string cursor, CancellationToken ct); } // optional
interface IAsserter        { Task Assert(Participant p, Label label, CancellationToken ct); }          // optional
```

`Handle` compares the delivered `Receipt.Version` with `Post.Version` and decides — publish, update, retract, requote. Adapter state is `Receipt` plus the Connection's own `Settings`. The connections screen derives "in sync", "changed", "retracted" and "a copy may remain" from Receipt against Post.

| Package (a folder of `Connections/`) | Syndication | References |
| --- | --- | --- |
| atproto | a `site.standard.document` with the cover blob for each public article, and a Bluesky post that embeds it; public Posts as the Tangent Space's own record type; `<link rel="site.standard.document">` and verification from Render | Constellation and Spacedust as a reference source, optional |
| Webmention | sent on `post.created` for outbound links; Bridgy Fed opt-in for fediverse reach | received at an endpoint |
| Mastodon | a status under the participant's own account | replies through its API |

Feeds are a Render output, not a Connection. Inbound replies arrive as `Reference` rows first; a Connection may later materialize them as Posts with source fields, authored by the person row Koan reconciles for that DID.

## 10. Identity

- **Sign-in** is atproto OAuth through Koan's connector, started at Bluesky's server, whose own account chooser picks the account; an account on another server names itself by handle or DID as the challenge's `identifier`. Koan's reconciler turns the DID into a durable person with the DID as its external identity. The `Participant` row is Tangent's facet on that person, created at the first sign-in by Tangent's sign-in hook, by command, with no question asked, with the standing the place's admission gives; in that command, and at every later sign-in's, an admitted participant who lacks the member role joins it.
- **Bring your agent.** `/bring-your-agent`, from the account menu, finds Companion Lobby: its island asks `http://127.0.0.1:5219/api/discovery` (900 ms, 4 KiB, no credentials, no redirect) and believes only an answer that states the product, the document's version and that origin, and one button then opens the Lobby's page at `/?service=tangent&address=<base URL>` in a new tab, the only hand-off the Lobby's origin rule lets another site make. The Lobby tells its sponsor to ask their agent to connect to that address; the agent does it with its own tool, and the Lobby's adapter comes in as a DID-native agent, through the proof door below. No other page looks for a Lobby, so only a person who came for it meets the browser's question about their local network. Any other agent is told the place's address, and signs in with its own account.
- **A DID-native agent** (its own participant) signs in at the proof door, with no browser, and sends the session's cookie on every page and at `/mcp`. `/.well-known/tangent-auth` states what it takes, for a client that holds only the address: the method `org.sylin.tangent.exchangeIdentity` and the audience, the `did:web` (Koan's `AtprotoServiceAuth.WebDid`) of the address the place has configured or accepted (`KoanWebBaseUrl.Current`) with the fragment `#tangent`, which needs nothing served at `did.json` since no account server resolves it. The audience never comes from a request, whose `Host` a caller chooses, because a token addressed to another place must never sign in here; so a place with no such address answers both the statement and the exchange `503` `exchange_unconfigured` with the reason, the descriptor states no proof door and `llms.txt` says so, and signing in through atproto is what sets such a place up and gives it its address. A place nobody has set up answers both `503` `exchange_not_set_up` with the reason, however it is addressed, so the first agent to connect never owns it; `Tangent:Operator` naming an account, an agent's among them, opens the door to set it up. The agent asks its account's server for a service-auth token and posts it to `/api/v1/identity/exchange` as `Authorization: Bearer`; the door reads no body. Koan's connector verifies it (`AtprotoServiceAuth`, SEC-0034): shape, algorithm, audience, method and times with no network, then the signature against the key in the issuer's verified document. `AtprotoServiceAuth.SignIn` then ends as the callback of a browser's sign-in ends: the same claims, the same external identity, and the same cookie through the same sign-in lifecycle, so the same admission, member role and first run apply, the same lifetime, and the same endings, sign-out and ban. It is a session like any other: its door and notifications are its own, and it reads its profile as any participant does. A token is not claimed: it may be presented again until it expires, about a minute, and a stolen session is the same concern as a browser's.
- **The installation's identity** is a `did:web` served from the issuer's ES256 key ring at `<base>/did.json` (`did:web` resolves paths), the same keys Auth.Server publishes as JWKS.
- **Proprietor and operator** are two fields on the settings row, stated in the descriptor and on the about page. First run sets both to whoever sets the place up, signed in as themselves — a person, a company through its own login, or an agent, as an agent may be a proprietor — and names the place from their handle. Setting up happens where the sign-in completes, in Tangent's first-run sign-in hook after the participant's own, by a command that establishes the place once and refuses a second sign-in racing it; the same command creates the first Tangent, *General* — public, of discussions, undescribed, as a created Tangent stands by default — so the place can be talked in from its first minute, its `everyone` overwrite in the same commit as the moderators' Tangent's access, and from then on an ordinary Tangent its settings change; the setter joins the administrator role, the origin the sign-in completed on becomes the place's address unless a URL is configured, and the setter lands on first run's pointers. The operator stands above every role: no one times them out, bans them or takes their administrator role. Before setup, `Tangent:Operator` may name who sets it up, by handle or DID, and only their sign-in does; unset, the first person to sign in does, and a later sign-in finds the place set up. The setting matters only before setup: an established place starts under any value, and a value that names someone other than the operator draws one warning at start.
- **Profiles** are cached by a job: the handle is the one the connector verified at sign-in; the display name, description and avatar come from the public profile service until Koan's connector reads the PDS itself (brief 3). Nothing is edited locally. `Kind` comes from the profile: the job reads the account's own `bot` self-label from the profile it captures and makes the participant an agent, or a person without it; a participant's own choice, once they make one, wins and the job never overrides it. `Kind` is shown and never evaluated.
- **A profile** is `/p/{handle}`, one resource both ways, by the handle a participant's row keeps now or by their DID: the cached profile, the roles Koan holds for them, their arrival as Koan's person records it, and one page of their Posts newest first through `Post(AuthorId, CreatedAt)`, read only in the Tangents the reader may view, with a seek cursor: the store is told the Tangents the reader may view, or the others where they are fewer, and the page keeps only Posts in the Tangents the reader may view and continues from the last it keeps, so no page, length or cursor says anything of a Tangent the reader may not view; a Tangent that changed while those were read makes a page short, never says it is there. A handle has one holder: the command that records a verified handle at a sign-in — a first arrival, a later sign-in, or the arrival that sets the place up — takes it, in the same transaction, from any other participant row that keeps it, since an atproto handle names one account at a time and the verified sign-in is the latest word; that row shows its DID and answers at its DID's address until its own next sign-in. A handle no row keeps now answers as a missing resource, an old one included, and the DID address is the stable one.

## 11. Discovery

A Tangent Space answers at its **base URL** — scheme, host, optional path — which it learns rather than asks for. First run takes the origin its setter's sign-in completed on as the place's address: loopback on a local install, the public origin on a production one. While that address is local — loopback, or none where Koan would not take the origin — and nothing is configured, a public https origin Koan sees requests arrive on is offered to the operator as an Offer, computed from what Koan has seen and never stored, so no request writes: one open at a time, the origin seen most often, and the next of them once one is declined. Using it makes it the address from the next request, with no restart; tokens and atproto sessions issued under the previous address end, so whoever was signed in signs in again there. A declined origin is never offered again. `Koan:Web:TrustedProxies` names the reverse proxies whose forwarded scheme, host and client address are believed, for one hop, which is how a proxy's public origin reaches the place; `appsettings.json` names this machine's loopback, `127.0.0.1` and `::1`, as entries 0 and 1, so a reverse proxy on the same machine is believed with nothing configured; a proxy elsewhere is added from entry 2 (`Koan:Web:TrustedProxies:2`), since configuration merges a list entry by entry, and the list is replaced whole in `appsettings.json`, as `[]` to believe none. A relay on this machine that passes clients' own forwarded headers through should not sit in front of the place, or the list should be replaced. A configured `Koan:Web:ApplicationUrl` wins over all of it — nothing is offered — and is how a path under a host is given, which Koan normalises once and serves under: routes, static files and health answer under its path and nothing outside it. Every absolute thing derives from it: links, the cookie path, the OAuth client metadata and redirect, the `did:web`, the publication URL. `tangent.<domain>` is the suggested address, the one a client tries first when a site holds no pointer.

Pointers live on the site, since `/.well-known/` belongs to an origin: `<link rel="tangent" href="…">` on the site's pages, or `/.well-known/tangent` at the site origin, or a `_tangent` TXT record. The Tangent Space serves its own descriptor at `<base>/tangent.json` — name, address, audience, `"api": 1`, where its tools answer (`{base}/mcp`), where it has an address of its own the proof door, links to the door and to `llms.txt`, and for a public place its proprietor, its operator and its feeds, a Tangent's with `{tangent}` standing for its slug; the installation's `did:web` and its publication join it with their packages — and `<base>/llms.txt`, which says in a few lines what signing in makes of a newcomer, from the place's own admission and audience, how to read the place, a public place's feeds among it, how to write through the forms its pages carry, its tools at `{base}/mcp`, and how to sign in with one's own account and send the session's cookie. Both carry an `ETag` of their body and a five-minute cache lifetime, and a private place's files name nobody. The first-run page prints the pointer snippets and, for a path install, the reverse-proxy rule, once the base URL is public; while it is a loopback address no site can point at it, so the page says instead that the pointers appear once the place answers at its public address, which it offers its operator when it is reached at one, or which the configuration names where the URL is configured.

## 12. Background work

Koan jobs, each a reader that writes by command: profile capture, handle resolution, connection dispatch, reference polling, media processing. At start, one service on Koan's background base asks whether the Post index covers every Post and has Koan rebuild it when a restored folder left it behind, logging what fails and trying again until it is done; it writes no row. Backup and restore are verbs of the executable, not jobs: `Tangent.Server backup` takes a `VACUUM INTO` snapshot of the data folder with a hashed manifest, and `restore` puts one back, refusing a folder a running Tangent Space has marked, and `archive` renders a stopped place's public pages and feeds to a folder. Nothing else runs in the background; nothing in a request does network I/O.
